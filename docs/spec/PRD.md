# PRD - Product Requirements Document

**Project**: pdf2md
**Date**: 2026-05-21
**Version**: 1.0

---

## 1. 产品概述

pdf2md 是一个命令行工具，用于通过远程 API 将本地 PDF、DOCX、DOC、TXT 文件批量转换为 Markdown 格式。

### 1.1 背景

用户拥有大量 PDF/文档文件需要转换为 Markdown 格式用于知识库构建。远程 API 提供 PDF-to-Markdown 的转换能力，需要一个本地工具来简化批量转换流程。

### 1.2 目标

- 提供简单易用的命令行接口，支持单文件和目录批量转换
- 通过可配置的远程 API 实现高质量的 PDF/文档转 Markdown
- 提供完善的日志记录，便于排查转换问题
- 处理文件名冲突，避免覆盖已有输出

## 2. 用户故事

| 角色 | 场景 | 需求 | 验收标准 |
|------|------|------|----------|
| 运营人员 | 将一批 PDF 合同转为 Markdown | 传入目录，一次性转换所有文件 | 目录下所有 .pdf 文件都被转换，输出到 output/ |
| 运营人员 | 转换单个 PDF 文件 | 传入单个文件路径 | 该文件被转换为 .md 并存放到 output/ |
| 运营人员 | 转换 DOCX 文档 | 支持 .docx/.doc 格式 | DOCX 文件与 PDF 一样被处理 |
| 运维人员 | 排查转换失败问题 | 查看详细日志 | 日志包含输入文件、重试次数、耗时、错误信息 |
| 运维人员 | 调整 API 配置 | 修改配置文件 | 无需改代码，修改 setting.json 即可生效 |

## 3. 功能需求

### 3.1 文件输入

| 需求 ID | 描述 | 优先级 |
|---------|------|--------|
| FR-001 | 支持通过命令行参数传入单个文件路径 | P0 |
| FR-002 | 支持通过命令行参数传入目录路径，自动扫描目录下所有支持格式的文件 | P0 |
| FR-003 | 支持的文件格式：.pdf, .docx, .doc, .txt | P0 |
| FR-004 | 不支持的格式输出警告日志并跳过 | P1 |

### 3.2 文件转换

| 需求 ID | 描述 | 优先级 |
|---------|------|--------|
| FR-010 | 读取输入文件并编码为 Base64 | P0 |
| FR-011 | 调用远程 POST API 将 Base64 编码的文件内容转换为 Markdown | P0 |
| FR-012 | API 请求失败时自动重试，重试次数和间隔可配置 | P0 |
| FR-013 | 网络错误（连接失败、超时）触发重试 | P0 |
| FR-014 | API 返回非 200 状态码触发重试 | P0 |
| FR-015 | API 返回无效 JSON 时不重试，立即标记失败 | P1 |

### 3.3 文件输出

| 需求 ID | 描述 | 优先级 |
|---------|------|--------|
| FR-020 | 将 API 返回的 Markdown 内容写入 output/ 目录 | P0 |
| FR-021 | 输出文件名使用原始输入文件的文件名（不含扩展名）+ .md | P0 |
| FR-022 | 如果输出文件已存在，追加 5 位随机小写字母后缀避免覆盖 | P0 |
| FR-023 | 支持多结果输出（API 返回多个 md_content 项时分别写入） | P1 |

### 3.4 配置管理

| 需求 ID | 描述 | 优先级 |
|---------|------|--------|
| FR-030 | 配置文件位于 conf/setting.json | P0 |
| FR-031 | 首次运行时自动生成默认配置 | P0 |
| FR-032 | 配置文件格式错误或关键字段缺失时快速失败并提示错误 | P0 |
| FR-033 | 配置值类型校验（如 max_retries 必须为整数） | P1 |

### 3.5 日志

| 需求 ID | 描述 | 优先级 |
|---------|------|--------|
| FR-040 | 日志输出到 logs/pdf2md-YYYYMMDD.log 文件 | P0 |
| FR-041 | 日志按天轮转（每天一个文件） | P0 |
| FR-042 | 日志格式：[YYYY-MM-DD HH:MM:SS] LEVEL  message | P0 |
| FR-043 | 日志包含：输入文件名、base64 大小、API 尝试次数、响应状态、耗时、输出文件名、错误详情 | P0 |
| FR-044 | 处理完成后输出汇总日志：Processed X files: Y success, Z failed | P0 |

### 3.6 命令行

| 需求 ID | 描述 | 优先级 |
|---------|------|--------|
| FR-050 | `python pdf2md.py <path>` 作为唯一执行入口 | P0 |
| FR-051 | 不提供 path 参数时显示帮助信息 | P0 |
| FR-052 | 传入不存在的文件/目录时输出错误并退出 | P0 |
| FR-053 | 全部成功时退出码为 0，有失败时退出码为 1 | P0 |

## 4. 非功能需求

| 需求 ID | 描述 | 验收标准 |
|---------|------|----------|
| NFR-001 | 性能：单文件转换主要耗时在 API 调用 | 本地处理（编码、写入）不超过 100ms |
| NFR-002 | 可靠性：单个文件失败不影响其他文件的处理 | 循环中捕获异常，continue 处理下一个 |
| NFR-003 | 可维护性：所有逻辑集中在一个文件中 | 核心逻辑不超过 500 行 |
| NFR-004 | 兼容性：Python 3.7+ | 不使用 Python 3.8+ 专属语法 |
| NFR-005 | 依赖最小化：仅依赖 requests 第三方库 | 无其他外部依赖 |

## 5. API 接口契约

### 5.1 请求

```
POST {api_url}
Headers:
  client_id: {client_id}
  Content-Type: application/json

Body:
{
  "files": ["<base64-encoded-file-content>"]
}
```

### 5.2 响应

```json
{
  "task_id": "a65f4a9a-aa11-4a99-b004-5d9d2b3f17a1",
  "status": "completed",
  "backend": "hybrid-auto-engine",
  "file_names": ["file_0"],
  "version": "3.1.8",
  "results": {
    "0": {
      "md_content": "<markdown content>"
    }
  }
}
```

## 6. 范围外（Out of Scope）

- PDF 本地解析（依赖远程 API）
- 异步/并发处理（当前为同步顺序处理）
- 图形界面（纯命令行工具）
- 认证/鉴权机制（API 仅需 client_id 请求头）
